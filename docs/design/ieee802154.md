# IEEE 802.15.4 radio interface and nRF52840 driver

Covers: drivers/src/base/IEEE802154_Radio.zig, port/nordic/nrf5x/src/hal/radio/ieee802154.zig, port/nordic/nrf5x/src/hal/radio/ieee802154_header.zig, port/nordic/nrf5x/src/hal/radio/ieee802154_phy.zig, port/nordic/nrf5x/src/hal/radio/ieee802154_src_match.zig, drivers/src/base/ieee802154_radio_tests.zig, examples/nordic/nrf5x/src/selftest/ieee802154.zig

## Purpose

The portable interface serves Thread (including Spinel RCPs), Zigbee and passive capture.
The nRF52840 implementation runs 2.4 GHz O-QPSK with interrupt-driven RX, legacy immediate ACKs,
unslotted CSMA-CA, retries and channel measurements. The tables describe the code as built, and
`file:symbol` references name the implementation sites. Open questions lists what is still
unresolved.

## Invariants

- One stationary caller-owned handle routes RADIO and TIMER3 through `R:owner`. Foreground
  calls are serialized and mask interrupts around shared state. Both IRQs run at equal
  highest priority. Hardware keeps latching events under the mask. The table prologue is for software dispatch. PPI and RADIO shortcuts still run directly in hardware. See `R:Radio.init`,
  `R:Dispatch.get`, `R:radio_interrupt` and `R:timer_interrupt`.
- Both ISRs and public entries marked NORMAL use Settle due deadlines
  first. The Masked resolver owns all natural transitions and retirement
  of consumed evidence. Sleep, admitted retune and enabled Disable or
  Deinit go directly to the explicit stop executor. Deinit checks unread results before aborting
  or releasing a disabled owner. Init never settles the
  incumbent, set_notify swaps its hook before settlement, and a null
  optional vtable slot never dispatches. The FIFO depth diagnostic also skips settlement. Every RADIO timestamp used for a decision
  passes Capture freshness, including on a stop or an IRQ entered early.
  Capture housekeeping is required for long-lived RX. Later decisions use the resolved logical context, including its channel and owner,
  while hardware finishes a safe handoff.
- Normal progression uses RADIO events and TIMER3 protocol deadlines. nRF52840 PS v1.11
  §6.20 specifies ramp-up, ramp-down, and RX END after the PHR-declared transfer.
  A software wait for a RADIO transition uses the shared bounded check. Failure of that check
  or a confirmed TIMER3/HFCLK stall enters the same fault path. It disables the radio,
  aborts outstanding owners, and updates the sticky fault record. Fault observation is armed
  only while enabled, including enabled idle with hardware off. The fault
  model assumes the IRQ and masked-foreground service bound in the timing table.
- Transmit, ED and CCA use non-preemptive admission (`TERM_NONE`). ADDRESS
  establishes RX ownership per Owned END. Policy and timed window exits preserve
  that owner. Captured ADDRESS strictly before a window cutoff
  owns the frame through END and any ACK. The sender's ACK acceptance rule uses
  corrected RX END relative to captured TX end. See `R:Radio.reserve_completion`,
  `R:Radio.service_phase` and `R:PollResponse`.
- **Settings pin.** While RX is armed, publication samples TIMER3 under the
  mask. An END captured in CC3 strictly before that tick uses the preceding
  generation. END at the publication tick or later uses the new generation.
  This applies to ordinary, listening-backoff, response and sender-ACK RX,
  including retained closes. CPU latch visibility and service order do not
  select the generation. Keep eight full snapshots in a ring, with one
  entry per distinct publication tick. A second publication on the same
  tick replaces that tick's entry. Classify against the newest entry whose
  tick is at or before the captured END. The selected generation
  supplies the entire filter, ACK disposition and power, and RX idle
  policy. The current generation governs the next arm
  (`R:RxSettingsVersions`, `R:Radio.publish_rx_settings`).
- **Settings history bound.** The timing table gives 4280 µs for a maximum
  PPDU, END latency and rounded-up DISABLED ramp-down. Back-to-back
  publication has no specified minimum call spacing. At TIMER3's
  1 µs resolution the worst case is 4281 distinct ticks in that interval,
  counting both endpoints. The fixed budget of eight snapshots holds the
  arm's baseline and seven changes, and bounded waiting handles larger
  bursts. When the ring is full, retire its oldest entry only when it is
  more than 4280 µs behind the newest committed entry and no live
  capture can select it. A departing arm with CC3 still at the sentinel
  prevents retirement. Elapsed wall time alone cannot extend the committed
  span. At verified arm retirement only the current
  generation survives. Wait for room for at most 4280 µs with an
  independent CPU bound. Run NORMAL on every iteration so protocol and
  lifecycle deadlines remain live. Recheck the budget immediately before
  publishing, including when NORMAL has just retired the arm. A miss
  faults before publication.
- An operation continuation exists only while its operation has no terminal.
  Terminal commitment clears its saved actions and deadlines under the same mask,
  before exposing the result. Every accepted TX, ED or standalone CCA produces
  exactly one queued terminal event.
  RSSI instead returns one result synchronously. `R:EventReservation` holds terminal
  capacity through polling, and TX also reserves every possible on-air start.
  RX reservation gates ADDRESS ownership in ordinary, response and listening
  backoff RX. Buffer-missing RX has no owner and cannot send an immediate ACK.
- Sleep, admitted retune and enabled Disable or Deinit use preemptive admission
  (`TERM_802154`). Use Close commitment to commit the abort under the mask
  without a prologue. Retire due and future deadlines of aborted work.
  Reconcile old completion latches in the explicit stop executor and prevent new work from starting. Fault, enabled Disable and enabled Deinit follow Lifecycle teardown and own
  a bounded masked DISABLED spin.
  Wake preservation ensures a requested wake is never lost to a clear.
  Enable uses Timer start before admitting work and preserves pending results.
  Deinit guard routes an enabled owner through teardown. After draining, a
  disabled owner checks the saved retirement state before software-only release. The lifecycle result table
  defines notifications and the RTC clock-fault backstop.
- `R:Dispatch.transmit` copies MAC bytes before return. `R:Radio.take_event` exposes one
  reusable delivered-frame buffer for RX and TX ACKs. Drain `I:poll` until null. Poll returns a fault found by its own prologue on that same call.

## Design tables

### 1. Phases

**Logical state overlay.** `R:Dispatch.state` applies this order under the
mask in every phase. An unowned or logically disabled handle reports Disabled.
A live admitted TX reports Transmit and a live admitted ED reports EnergyScan.
Standalone CCA owns a saved Receive or Sleep projection from its admission
state because `I:State` has no CCA value. Keep each operation's projection
until Terminal commitment, including through stopping, a masked END close
and immediate ACK. With no live operation, report Receive for live RX intent or
ownership, including an owed immediate ACK, and Sleep otherwise. In-place RSSI
adds no public state. A post-poll response window can live in `rx`, `auto_ack`
or a response-origin `stopping` handoff until expiry or admission
retires it. Its TX channel is separate
from the requested RX channel. Quarantine is not a phase: `R:Radio.quarantined`
marks a logically disabled owner in `off` whose producer retirement could not be
verified. The tables show it as a separate `off`, quarantined column.
FG means serialized foreground under the interrupt mask. IRQ means RADIO or TIMER3.
TIMER3 carries protocol deadlines. RADIO provides ramp and drain evidence to
the Masked resolver. A backoff has a TX-owned slot deadline and an RX mode
on the TX channel when idle RX is enabled. The synchronous END close and
immediate ACK can own the hardware while that slot remains live.

Ordinary RX has no dispatchable drain phase. When END needs service, the
current resolver masks END with readback and waits for DISABLED within
the same masked dispatch. It keeps the old captures and settings through
classification, or faults on a missing edge. This follows the bounded
Nordic `wait_until_radio_is_disabled` precedent under Bounded RADIO waits.
References to frame drain describe this interval or an already-retained
`stopping` handoff. Sender ACK retains `ack_drain` only when cutoff service
finds a qualified ADDRESS whose candidate must still reach END.

### 3. Events × phases

RADIO shortcuts are off unless the corresponding phase cell lists them. TIMER3 has no
SHORTS enabled. Captures and the immediate ACK launch are PPI routes; clearing a latch
alone cannot revoke a task already triggered by a shortcut or PPI.

The shortcut owner programs the complete set for its phase and removes that set at
quiescence before exposing the next packet or task (`R:Radio.begin_disabled`). During
a retained RX close, keep ADDRESS→RSSISTART, END→DISABLE and DISABLED→RSSISTOP until
DISABLED is reconciled. Remove the RXREADY→START path as part of closing new admission.
`R:commit_boundary` fixes the ownership boundary for that close. A stop revokes TX launch shortcuts while retaining its captures
until the owner is resolved. Normal TX and immediate ACK retain PHYEND→DISABLE.

IRQ entry masks serviced sources using INTENCLR with readback before interpreting
the events. Masking leaves latches, PPI and shortcuts intact. Re-enable a source
only for a phase that needs it. An already-due software deadline is handled by Deadline arming below. CC0 is reused for the owned RX close watchdog after ADDRESS. In
auto_ack its hardware launch route uses its own future margin. On a stop, the `R:Close` record and the
cleared deadline record are saved under the mask. Apply **Deadline arming** in the timing rules to every
CC1 protocol arm, including continuations carried through a natural stop. CC5
keeps its own `temp_deadline` across phase stops. An explicit abort disarms the previous CC1 deadline and commits saved-owner results. TX start
capture stays live until quiescence for attempt notification.

**TEMP service.** CC5 has its own record, `temp_deadline`, for the enabled lifecycle. Phase changes
leave the arm and pending sample intact. After Timer start, enable arms CC5 and starts a fresh sample.
The NORMAL due-work table owns CC5 service. Consume DATARDY only
for a sample started in the current lifecycle.
Clear DATARDY before the next TEMP START. If the conversion is still pending, keep the old adjustment and leave
the sample running. Rearm through `R:Radio.program_compare` on CC5 (`R:Radio.resolve_enabled`). Keep the CC1 record and hardware untouched. Disable disarms
CC5 and retires the active sample through Lifecycle teardown before sealing publication.

**Task ownership.** RXREADY→START handles packet RX when armed.
RXREADY→CCASTART alone starts either CCA. READY→EDSTART alone starts ED.
The Masked resolver observes the latch and arms the associated deadline. Software TX
uses the resolver’s TXREADY branch for START and immediate ACK uses TXREADY→START.
CCAIDLE→TXEN starts clear CCA TX ramp and CC0 PPI starts immediate ACK ramp.
ADDRESS→RSSISTART handles packet RSSI. In-place RSSI uses RSSI sample ownership for foreground attribution.
END, PHYEND, EDEND and CCABUSY shortcuts own their normal DISABLE paths.
Standalone CCA clear requests DISABLE in software. Nordic
`irq_handler_edend` and `nrf_802154_trx_energy_detection_finished` complete ED,
and `irq_handler_ccaidle` and `irq_handler_ccabusy` complete standalone CCA
through `nrf_802154_trx_standalone_cca_finished`. These paths have no
missing-result Timeout outcome. This driver uses the shared bounded check and
Fault transition when expected measurement evidence fails to arrive.
Explicit stops revoke task producers with readback and use RADIO evidence to
decide whether to request DISABLE. Natural owned RX preserves its END→DISABLE path.
Keep ADDRESS and END capture routes until the departing evidence is reconciled.

**Slot service.** NORMAL dispatch services the live slot (`R:Radio.slot_due`) at
or after its absolute deadline. Equality is due. Use the saved
close boundary before consuming DISABLED or selecting a continuation. A late
END cannot change the boundary. Only a slot decision taking a new boundary
can apply the ownerless-slot exception. A previously committed owner stays
owned. Recheck the slot after the bounded END wait and final disposition,
including an ACK declined during setup. The frame stays busy through
that decision. An
unexpected buffer-missing DISABLED faults before the slot decision.
Immediate ACK stays busy until PHYEND or DISABLED latches. Sample those
latches at the slot decision. If the ACK has finished, carry CCA through
quiescence without a busy charge. Hold the next RX arm until the decision.

In listening backoff use Close commitment and `R:commit_boundary`. During
backoff-origin stopping use the existing close record. If owned,
charge Busy assessment once and preserve normal frame and ACK completion.
If unowned, retire the slot deadline and close or attach CCA to the close
in progress. Carry the recorded decision through quiescence, including
when an explicit stop cancels CCA.

With idle RX off and hardware quiescent, start CCA immediately. If an
old TX CCA close or a finished immediate ACK has yet to reach DISABLED,
complete that hardware phase and run CCA once for the live TX at
quiescence. The active close owns its continuation, so it cannot also
rearm RX. An explicit abort retires the slot and its continuation.

Nordic `frame_transmit` tests live core ownership at callback service.
`nrf_802154_core_transmit` calls `current_operation_terminate` under its
critical section. The helper samples `receiving_psdu_now` once, tests
`can_terminate_current_operation`, then calls `nrf_802154_trx_abort` and
notifies using the saved sample. An ADDRESS that arrives after a clear
sample is outside that accepted RX operation. OpenThread `SubMac::HandleTimer` dispatches
`BeginTransmit` from the current state.

**Busy assessment.** Charge a hardware CCABUSY only in NORMAL dispatch.
Explicit stops abort without charging that result. NORMAL
dispatch also charges due busy software slots, once per eligible slot. Set `NB = NB + 1` and `BE = min(BE + 1, macMaxBE)`. If the new
`NB > macMaxCSMABackoffs`, save `channel_access_failure` as the earned TX
terminal in the operation record. Retire the slot and clear the TX
continuation per Terminal commitment. Otherwise
`R:Radio.begin_backoff` draws from `[0, 2^BE − 1]` unit backoff periods and
arms the absolute deadline from service time per Deadline arming. This follows
IEEE 802.15.4-2006 §7.5.1.4 Figure 69, step (4) and the return to step (2).
Nordic `channel_busy` applies the same update.

A retry deadline starts at the busy service even in backoff-origin stopping,
synchronous END close or immediate ACK. Carry it across quiescence and service it when due,
including zero delay while the same owner remains. Only hardware continuation
waits for the old frame, any owed ACK and DISABLED. On a clear decision save
the authorization to start CCA per Slot service. Continuations keep that
decision across DISABLED without retesting the old slot or drawing a retry.
For a departing backoff RX frame, publish its disposition, settle any
remaining due slot against the saved owner, then release the owner before
preparing a replacement arm. Whether or not a disposition was published, pend RADIO
under Wake preservation and prepare the replacement in a separate NORMAL
dispatch. A slot due after the decision uses the ownerless continuation.
A fault in that later dispatch leaves the published result intact.
NORMAL service of hardware CCABUSY saves the busy decision and verifies
DISABLED within the same dispatch. Preserve the surviving retry's absolute
deadline through that check. On exhaustion, publish the earned
channel_access_failure after verified retirement or carry it into teardown,
with no retry slot.

**Terminal commitment.** A continuation exists only while its operation has no
terminal. Under the mask, commit the TX terminal (channel_access_failure, no_ack,
sent, acked or aborted), ED/CCA completion, and clear
that operation's continuation and deadlines in the same step. Exhaustion in
retained stopping, synchronous END close or immediate ACK leaves no TX
continuation. Finish the owned frame and any owed ACK. Publish the RX
disposition, release its owner and commit the earned terminal in the same
transition. Defer only hardware setup. If a stop or fault takes over before
publication, it publishes the earned terminal after disposing of RX. A
CCABUSY latch still unserviced when the explicit stop executor starts earns no terminal. A stop or fault
after publication preserves the queued result. An acked terminal may
create a new RX context through Window admission. It does not retain the TX.
Apply Admission reopening after committing a terminal and its continuation.
If its unread reservation is still a Busy guard, apply the same check when
poll releases the reservation.

**RX reservation.** Reserve a FIFO slot before admitting packet RX, separate
from operation reservations. ADDRESS claims the slot for delivery or abort.
Retain it through synchronous END close, retained stopping and immediate ACK. Release an unused slot when RX exits
or rejects the frame. Without capacity, buffer-missing RX stays in RXIDLE
without packet START, DMA or ADDRESS ownership. It is unowned for Slot service.
Entry uses Overrun report. When poll frees a slot, restore RX only for the eligible logical context
from Settle due deadlines first. Reconcile any latched claim through Owned
END. An expired response arm cannot be restored. If the resolver selects a
different receive context, wait for old hardware quiescence and arm only the
new context with its own reservation. Any poll-driven close uses Close commitment
before re-arming. A still-live context keeps its original
slot or cutoff. Sender ACK RX
uses the reserved TX terminal. Nordic `nrf_802154_trx_receive_is_buffer_missing`
reads `m_flags.missing_receive_buffer`, and `nrf_802154_trx_receive_frame` omits
packet START without a buffer.

PS v1.11 §6.20, Radio states and IEEE 802.15.4 Receive sequence, places address
monitoring after START, when baseband processing and packet DMA are active.
The buffer-missing configuration therefore does not observe drops. The Event
throughput GAP asks whether there is a documented alternate configuration.

[nRF52840 RADIO specification](https://docs.nordicsemi.com/r/bundle/ps_nrf52840/page/radio.html)

**Overrun report.** Overrun tells the consumer that frames may have been lost
for lack of RX capacity. Buffer-missing RX cannot observe a drop, so
`R:Radio.start_rx` reports overrun when it issues RXEN without a slot, once per
episode: `R:Radio.starved_reported` suppresses further reports until poll
frees a FIFO slot. Later buffer-missing arms in the same episode, such as a
retune, a backoff slot or a response window, report nothing. An arm whose
cutoff passes during setup issues no RXEN and reports nothing. Nordic
`nrf_802154_core.c` does the same: `rx_init_free_buffer_find_and_update`
calls `notify_no_rx_buffer`, which reports `NRF_802154_RX_ERROR_NO_BUFFER`
only while `m_no_rx_buffer_notified` is clear and then sets it, and
`nrf_802154_core_notify_buffer_free` clears it when the consumer frees a
buffer. The marker uses no FIFO slot: it follows the FIFO events queued when
it was set and coalesces with an unread marker (`R:Radio.report_overrun`):
it stays where the first unread episode began, and later episodes fold into
it until poll reads it.
Mode stop and Lifecycle teardown never publish a drop for discarding an arm
or aborting an owner. An owned frame is never dropped
for capacity: only a reserved arm owns a frame, and its slot stays free until
the frame is published or the arm retires. Only the owner's frame or its
abort uses that slot, and Operation admission counts it or refuses the owner.
`R:Radio.accept_received_frame` checks this invariant at run time: a full
FIFO there takes the Fault transition with `event_reservation` without
storing the frame. `R:Radio.enqueue` records the same fault when the owner's
frame or abort finds no slot, and counts the lost result as an overrun. The
buffer-missing detection GAP remains open.

**Receive request identity.** Each explicit receive records its channel and a
new sequence. ADDRESS binds only per Receive request context. On renewal, use a masked
ADDRESS-latch check as the request boundary: assign a previously latched claim
to the old request and a later claim to the new request. Retain an established
sequence unchanged through synchronous END close, immediate ACK and retained stopping.
With idle RX off, consume the request only when the frame passes the selected
RX policy, is actually delivered and its recorded sequence still matches. Good
FCS is required unless bad-FCS delivery is enabled and the frame is delivered
under that policy. Rejected, undelivered and aborted frames consume nothing.
A newer renewal stays pending, subject to any admitted operation and
Idle-policy change. Sleep,
Disable, Deinit and fault retire the request. An accepted retune publishes a
new request after reconciling the old owner. Requested-channel idle RX arms
only for a live explicit request or current rx_on_when_idle=true. Protocol ACK
and response RX use their own admission rules.

**Owned END.** In ordinary RX and listening backoff, a current-arm ADDRESS
latch plus a reservation establishes ownership independently of CC4.
While closing, use only the recorded `R:commit_boundary`. Carry any qualified
origin and ownership through synchronous END close, retained stopping and explicit stop or fault
reconciliation. Record an ordinary or listening-backoff owner before
validating its timestamp. A failed CC4 capture then triggers Fault
transition and the undelivered owner gets one rx_error.aborted plus the
sticky fault. A normal delivery still needs validated timestamp evidence.
For a response window’s synchronous END close or response-origin stopping, the
shared resolver additionally requires ADDRESS validated by Capture freshness
and strictly before the original window cutoff. Use that saved cutoff even after clearing its
scheduler entry. An ADDRESS at or after cutoff establishes no owner, binds
no request, delivers no frame and owes no ACK. Retire its evidence and release
the unused reservation when quiescent. RADIO-first and TIMER3-first both apply
this predicate before binding, resolving END or classifying ACK eligibility.
A qualified owner lasts through hardware END, DISABLED and any owed ACK, even
after cutoff. Use the same resolver during close, including when a compare
observes the latches first. Sender ACK RX and ACK drain require valid capture evidence per Sender ACK
timing. Explicit abort and fault use saved ownership per the lifecycle
table. Timed contexts cannot establish ownership from the latch alone.

**Window expiry.** In NORMAL dispatch, service a due response cutoff
in live RX, synchronous END close, immediate ACK or response-origin stopping. Apply

Consume the cutoff once, clear its deadline and mark the context expired. A
qualified owner finishes normally. With no owner, consume the DISABLED

can establish verified quiescence. Otherwise finish the stop if needed.

live Window renewal on natural expiry. Use RX continuation after quiescence and apply
Admission reopening when the retirement or subsequent close releases a guard.
Settle due deadlines first. Successful TERM_NONE admission retires a still-live
window early, consuming its future cutoff and removing its RX continuation.
Retain any old owner and its cutoff evidence through close, without allowing
a new response arm. The admitted operation is then the sole saved continuation.
DISABLED executes it after old-owner completion. Expiry cannot replace it.
Early retirement by TERM_NONE discards only a still-deferred window renewal.
A renewal already promoted by expiry remains the outstanding explicit request
behind the admitted operation. Mode stop or lifecycle teardown cancels both as well.

**Window renewal.** A receive on the TX channel of a live response window,
while the current tick is strictly before its cutoff, succeeds without
restarting RX or changing the cutoff, even during a response-origin synchronous END close or
owed ACK. Record the newest channel and sequence as a deferred renewal of
that window. It is not eligible as an ordinary explicit request, and no
window frame binds or consumes it. On natural expiry, promote that renewal
to the outstanding explicit request and atomically set the persistent
requested channel to its channel. A later request or policy close can
supersede or retire the deferred renewal by sequence before promotion.
Consuming the promoted one-shot later clears only the request, so CCA and
idle RX keep that channel. Apply RX continuation at quiescence. Repeated matching calls update the
saved renewal without extending the window.

**RX continuation.** NORMAL dispatch applies the live physical
continuation. Resolve intent even while a retired physical
arm is stopping. Complete the departing frame and any owed immediate ACK
at verified quiescence. Save the verified ACK status before retiring its
arm. Publish the RX disposition and any earned terminal, then pend RADIO
under Wake preservation, even when a filtered frame left nothing to publish. The next NORMAL dispatch applies the saved
hardware continuation using this order:

1. Resume a live admitted foreground operation. Carry any live backoff slot
   or committed decision with its absolute deadline.
2. Resume a live response window on its saved TX channel until its original
   cutoff. Use the prologue’s already-settled deadlines.
3. Arm RX for an outstanding explicit request on that request's channel.
4. Apply idle policy on the requested RX channel, or leave RX off.

Finish any deferred policy close on owner completion before choosing.
Its request retirement uses the sequence already committed by the settings helper.
When synchronous END close owes an ACK, defer this choice until normal ACK completion.
Explicit mode stop and lifecycle teardown have their own continuations.
After resolving hardware and ownership, apply Admission reopening.

   retire RADIO power as needed, and verify both before sealing. Verify
   capture-route revocation before clearing PACKETPTR or reusing CC0, CC3
   or CC4. A persistent mismatch quarantines the owner and retains its DMA
   storage.
2. Use Capture handoff. Retain every old capture route and its validity
   evidence through bounded RADIO quiescence and reconciliation, including
   READY/RXREADY→CC0, RX ADDRESS→CC4 and END→CC3, and TX ADDRESS→CC3
   and PHYEND→CC4. Fold a failed check into the active teardown and apply
   Failed retirement if quiescence fails. During teardown keep the handle
   installed and prevent reuse of potentially live DMA.
3. Reconcile old ownership and captures into saved results. Keep the
   accepted frame in its software slot before attempting ACK setup. A
   fault can abandon the ACK and publish that frame even if TXEN was never
   armed.
4. Verify producer retirement before committing saved results. Retire
   old capture routes before clearing their storage. Retire the remaining
   producers and fold failures into the active executor. Quarantine an
   owner whose producers could not be retired.
5. Write all bits to INTENCLR on RADIO, TIMER3 and TEMP and read back
   each interrupt-enable mask (PS v1.11 §§6.20, 6.30 and 6.28).
   Disable both RADIO and TIMER3 NVIC lines. Record any failed readback
   in the active executor. TEMP has no enabled NVIC route.
6. Commit saved results once in the executor. Queue any proven TX start before
   the terminal and apply Fault timestamps when teardown failed. Retire
   the request, seal publication, and clear enabled. Keep the lines
   disabled and clear pending before delivering the saved wake directly
   to the installed notify hook. Enter off after verified retirement or
   quarantine after unverified retirement. Unmask with both NVIC lines
   disabled. Perform no further peripheral cleanup while quarantined.
   Disable or deinit returns `error.HardwareFault` for any fault found in
   its teardown. Deinit retains the handle on that error.

**Faults within teardown.** Once Disable, Deinit, Mode stop or a fault
owns teardown, every subsequent failure, including Capture freshness,
belongs to that active executor. Record each failure once and continue
with the evidence available. Never re-enter teardown or repeat a failed
capture wait. A Mode stop that discovers a fault cancels its requested
mode change and extends the same masked executor through lifecycle
retirement and sealing, using its saved ownership and completed steps.
Commit each saved result once in the executor, with Fault timestamps. If the
fault arrives after result commitment, clear timestamps on this
teardown’s still-masked results in place. Update Sticky fault before
step 6 seals publication, preserve the final wake and leave HAL Disabled.
Disable and Deinit return HardwareFault. Sleep and retune return Aborted.

**Mode stop.** TERM_802154 sleep and accepted retune use the foreground-owned
masked sequence from Lifecycle teardown for the RADIO handoff only. Use
Close commitment before revoking
launches. Use Capture handoff through a bounded spin on DISABLED and reconcile
the old owner once in `R:Radio.execute_stop`. Retire old DISABLED and hardware pending before
arming the requested mode. Sleep retires the old request and leaves RADIO off.
Retune replaces the old request and arms its new channel.
Use Wake preservation across the old-source clears. Restore the wake after
the last clear, then unmask and return. Keep the enabled TIMER3/TEMP lifecycle running on success.
On failure use Faults within teardown.

**Fault transition.** Runtime fault sources, including the RSSI waiter, a setter
close, an ISR and enabled-idle observation, call `R:Radio.enter_fault` and use
Lifecycle teardown when no teardown is active. Otherwise apply Faults within teardown. An ISR that entered teardown exits without normal continuation.
After the mask is released, state() reports Disabled.

**Fault timestamps.** `I:RxFrame.timestamp_us`,
`I:TxStarted.timestamp_us` and `I:TxDone.timestamp_us` are `?u64`, null
only on the fault path. The saved `R:commit_boundary` governs RX ownership during fault reconciliation.
A valid raw capture can establish timing eligibility at that boundary or
transmission but cannot establish now_us time on this path. Publish null
for every timestamp field in a fault result, including an ACK frame carried
with a result. The undelivered-frame `rx_error.aborted` carries no timestamp.
An accepted frame delivered by the fault path has a null RX timestamp.
Preserve verified ACK flags, or clear them if the ACK had not been verified.
Successful TIMER3 captures, including valid PHYEND fallback, do not change
the timestamp rule. Preserve results already published by a prior dispatch,
including their timestamps and ACK flags. If a fault is first found during retirement, clear the
timestamp fields of the results appended by the current teardown while
still masked and before unmasking. Preserve their order and count. Apply the
same rule to results from a Mode stop that escalates to fault.

**Deinit guard.** Under the mask, an unowned call succeeds. For an owner,
check Consumer backlog first. A nonempty backlog returns Busy before any
hardware access or release. Then branch on logical enablement:

- Enabled: run Lifecycle teardown directly. Lifecycle teardown commits the close once and aborts in the explicit stop executor.
  Deinit passes control to the executor after the backlog guard. A fault during this teardown returns
  HardwareFault with routing retained. On successful teardown, recheck backlog. Return Busy with
  routing retained if new results remain unread. Otherwise release routing.
- Disabled on entry after Disable or fault: with backlog clear, check
  the saved retirement state in memory. If verified, release routing.
  If unverified, return HardwareFault and keep routing, the handle and
  its DMA storage quarantined until chip reset. Neither branch runs a
  prologue, hardware wait, verification, reset or teardown.

**Consumer backlog.** Under the mask, backlog is FIFO non-empty OR overrun
pending OR sticky fault set. Use this predicate for event backlog, hook
registration and poll's more-pending check after a pop. A newly installed
hook gets a wake for existing backlog, including a fault-only record while
disabled. Poll requests another wake when backlog remains, using the
enabled or disabled delivery path in Wake preservation.

**Notify swap.** On an owned handle, `set_notify` atomically installs,
replaces or removes the hook under the mask before running the prologue.
Settlement may fault and let the teardown executor notify the new hook
directly. With a null hook it invokes no callback. If the executor did
not deliver a wake on this call, request one for an installed hook when
Consumer backlog or a saved progress wake remains. Both removal and
replacement succeed even if settlement faults. Delivery resolves the
current hook under the mask. The old callback cannot run after removal
or replacement returns. Its old context can be released
at return.

**Poll drain.** Run the prologue, then pop under the mask, including if
settlement faults. A newly found sticky fault is returned by that same
call before FIFO results. Preserve the ordered overrun marker and use
Consumer backlog for further wakes. A final wake already delivered by
teardown in this call covers any backlog left after the pop. Return null
only when Consumer backlog is false after settlement. A caller without a hook can drain
the fault and terminals by polling alone. Poll may release reservation
bookkeeping after a fault. It cannot rearm a disabled receiver. A buffer-missing
re-arm uses Close commitment and returns a fault discovered there on the same call.
If freeing FIFO capacity selects re-arm, verify quiescence and producer
retirement before dequeuing. Account for the FIFO slot during replacement
setup without removing the head. If a cutoff crosses during setup, verify
retirement of that unlaunched arm before committing the dequeue. Drain returns a new sticky fault first and
keeps the FIFO head. Fault-preserving poll returns null and keeps both
the fault and the FIFO head.

**Admission reopening.** Admission reopens ⇒ wake. Under the mask, after a
natural close (including one with no owner), filtered frame release, normal
RX or ACK completion, window expiry, or operation terminal, request a
progress wake if an admission guard that caused Busy has been released and
a previously blocked class of call can now be admitted. Compare the guards
before and after the transition while admission is enabled without requiring a prior caller registration
or an event to publish. If clearance depends on DISABLED or on polling a
reservation, perform the check at that completion. Use Wake preservation
for any pending IRQ clears.

**Wake preservation.** A requested wake is never lost to a clear. Set
`notify_pending` for every wake request. Under the mask, before each
hardware IRQ-pending clear, OR the flag into the saved progress-wake bit.
Preserve that bit across all cleanup steps and across escalation of a mode
stop to fault teardown. After the final clear, while the handle remains
installed, retain one pending wake if the saved bit, a newly requested
wake or Consumer backlog is true, even with an empty FIFO and no sticky
results. For a successful mode stop that keeps the lifecycle enabled,
re-pend RADIO. For lifecycle teardown and failed Enable cleanup, the
active executor consumes the wake and calls the current hook directly
under the mask after the final clear and state commitment. After teardown,
wakes while disabled never depend on RADIO or TIMER3 vectors. Disabled
Notify swap and Poll drain use the same direct delivery for their own
wake requests. The enabled RADIO IRQ consumes a pending wake before
calling the hook. After a fault tears down the lifecycle, its IRQ returns
without a second notification. With no hook retain the software wake for
registration without pending either vector while disabled. The hook
must not reenter the radio. Successful Deinit ends notification routing
at handle release.

**Sticky fault.** Lifecycle teardown updates this record before sealing publication,
including any failure in the final interrupt isolation. The first fault since the sticky record was read sets pending, records its reason,
and sets count to one. Later faults increment the count up to the u32 maximum
and preserve the first reason. A maximum count means at least that many faults.
Enable and Disable preserve any unread record. Failed Enable startup may
append to it while the FIFO remains sealed, as the sole startup
publication exception. The vtable's fault_pending() returns a masked
snapshot {pending, reason, count} without a prologue, hardware access
or consumption. An unowned handle reports no pending fault and zero
count. The reason is meaningful only while pending. Poll atomically returns and clears
one `I:Event.fault` with the reason and count before reading any FIFO event or overrun.
Operation terminals retain their reservation and order.

**Normal DISABLED evidence.** The resolver uses the current phase and the
active close to interpret DISABLED once. For an active close, consult
its record. RX ownership comes from the saved ADDRESS ownership read.
DISABLED attribution comes from the saved commitment decision, including
the owned natural-frame exception in Close commitment. Neither commitment read repeats. A late
ADDRESS stays unowned and a clear slot stays clear. TX CCA busy service
verifies and consumes DISABLED within its dispatch before taking a live retry
target. An ordinary completion selects a
continuation only when no close already owns it.

In armed packet RX, END produces normal DISABLED. On either END-first
or DISABLED-first service, take both commitment reads before any bounded
wait. Classify and ACK only the owner recorded there. A late-visible
ADDRESS during the END wait cannot be adopted. If the saved decision
rejects the frame, a saved DISABLED and valid current-arm END capture
already prove departure. Consume that close without waiting for the END
latch and continue without delivery or ACK. Listening
backoff rechecks the slot at this commitment decision. If the slot is
already due, DISABLED is already set and ownership was not established,
discard the frame and proceed to CCA without a busy charge. A slot becoming
due after commitment is settled against the saved owner. In immediate ACK, PHYEND supplies normal ACK completion.
If required evidence is absent, use the bounded check, then Fault transition
if it remains absent. An already committed RX close or abort uses its
saved stop outcome instead. The sender ACK candidate resolver has its own
no-candidate outcome. Ordinary, response and listening-backoff buffer-missing
arms have no packet START or END producer. If DISABLED latches without a
committed close, the Masked resolver takes the unexpected-DISABLED branch
directly to Fault transition. Fault transition preserves explicit-stop outcomes,
including the live backoff TX terminal. A committed close uses the saved
stop outcome.

**Close commitment.** Every new close uses `R:Radio.commit_close`
under the RADIO/TIMER3 mask, using these two reads in order:

1. **DISABLED commitment read.** A latch that arrives after this read
   belongs to the new close, subject to the owned natural-frame exception
   at read (2). In ordinary,
   response and listening-backoff buffer-missing RX, a latch already set
   with no committed close is the unexpected-DISABLED fault. Packet START
   and END→DISABLE are absent and DISABLED→RSSISTOP cannot trigger itself.
   This check is a best-effort detector of an anomaly outside the model.
   Use the saved latch once in Fault transition. The reserved-backoff
   late-frame exception applies only to slot proceed with no owner
   recorded. Attribute that late frame's DISABLED to the slot close and
   discard the frame. An established owner entering the explicit stop executor retains its
   disposition even if END and DISABLED are already latched.
2. **ADDRESS ownership read.** Use `R:commit_boundary` to record the
   departing RX owner. For every natural handoff, a reserved frame found
   owned at read (2) keeps its own END→DISABLE through completion,
   whenever END latches. Complete the
   frame or sender-ACK candidate on that latch, then finish any owed ACK
   before continuing per Close continuation. This applies
   to policy closes, housekeeping, both expiries and an admitted
   operation waiting behind RX. The ownerless slot exception remains
   in read (1). For any natural close, if read (2) rejects a frame
   whose current-arm END→DISABLE was already set at read (1), discard the frame and
   consume the saved latch once as completion for verified quiescence.
   Do not wait for another DISABLED if the radio is already quiescent.
   The buffer-missing fault and ownerless slot exception still apply.
   In the explicit stop executor use the saved owner and reconcile any existing END and DISABLED
   without normal frame completion.

**Close boundary (`R:commit_boundary`).** The ADDRESS ownership read inside `R:Radio.commit_close_kind` is
the frame ownership boundary for every close. It records `owned` and `address_tick`
in the `R:Close` record, tied to the departing arm. Use already-established
ownership or the eligible current-arm ADDRESS latched at the read.
Exclude the frame already rejected by the reserved-backoff exception. Use
Owned END and Sender ACK timing for reservation and cutoff eligibility.
Save the sampled latch or established claim under the mask before
validating its capture. Cache that capture once under Capture freshness.
An ordinary or listening-backoff claim remains owned if CC4 validation
fails. A timed claim uses its original cutoff predicate. Preserve an already-accepted frame or owed ACK under its saved
disposition. The ADDRESS read concerns RX ownership. TX start evidence
continues to use Capture handoff and TX start reporting.

An owned natural close retains the frame through END and any owed ACK,
then follows Close continuation. An owned explicit-stop close follows Lifecycle result paths, even when END and
DISABLED are already latched. An undelivered frame gets one abort.
An already accepted frame with an owed ACK is delivered once with the
ACK abandoned. A frame whose ADDRESS appears after the read is unowned. Discard
it without an RX result, ACK, overrun or slot charge, even if its END
triggers DISABLED. Attribute that DISABLED to the close. An already
expected shortcut completion for an owned frame retains its natural or explicit-stop
disposition. For phases without an RX arm, the RX record has no owner.

Carry both recorded decisions through Owned END, DISABLED and fault reconciliation.
A close already in progress supplies its record to any slot, policy,
expiry or explicit continuation that takes it over. Never repeat either
commitment read for that departing arm. If a fault starts a new close,
take its boundary once. If a fault occurs inside a committed close,
carry the existing record into fault reconciliation. When an explicit stop executor (Mode
stop, lifecycle or fault teardown) is active, apply Faults
within teardown in that executor. Otherwise enter Fault transition,
which takes ownership as the teardown executor. A natural close alone
does not own teardown. This includes slot proceed, policy close,
housekeeping, response or sender-ACK expiry, buffer restoration and
TX/ED/CCA admission.

Apply this rule to slot proceed, policy close, housekeeping re-prime,
response expiry, sender-ACK expiry, mode stop, retune, Disable, Deinit,
fault and every other hardware handoff. Direct explicit stops bypass settlement.
NORMAL callers use the rule at handoff. Apply Close fault return to
pre-publication faults. A policy close scheduled by an already published
setter reports failure through the sticky fault and saved results.

**Close continuation.** Run the saved continuation once at verified
quiescence after any frame disposition and owed ACK. If the frame's
DISABLED already established quiescence, as with a filtered frame with
no ACK, continue immediately. Require a separate close-owned DISABLED
only if another hardware stop is needed, such as when RX remains armed.
This applies to policy close, a live slot's CCA continuation, re-prime,
expiry and an admitted TX, ED or CCA. Slot service and Terminal
commitment still govern whether the continuation exists.

**TX attempt completion.** In NORMAL dispatch, route every DISABLED in `tx` and
`tx_cca` to `R:Radio.handle_tx`, including the zero-backoff entry. Resolve
evidence for the current attempt in this order:

First, a valid current-attempt PHYEND for a launched attempt proves
transmission in either phase. It takes precedence over measurement
settlement in `tx_cca`, including when the clear CCA latch and saved
clear record are both absent. Validate and save PHYEND before retiring
its route. Retire any outstanding assessment compare. If DISABLED has
yet to latch, verify it with a bounded wait in this dispatch. Failure enters
Fault transition. After verified retirement, reconcile TX start reporting
before any normal terminal. If TX
requested an ACK, use Sender ACK timing from the original PHYEND and Deadline
arming. Arm sender ACK RX on the TX channel before cutoff, or resolve an
already-due cutoff as an unowned wait using the same ACK candidate rules.
Repeat that check at RXEN after capture and compare setup.
With no ACK requested, commit sent, clear the operation continuation and use
RX continuation and Admission reopening.

With no PHYEND evidence, NORMAL dispatch uses Saved measurement result
for TX CCA. On hardware busy, apply Busy assessment once and verify
DISABLED synchronously. An explicit stop leaves unserviced CCABUSY to the explicit stop executor.
After verified retirement, execute only a still-live retry using its absolute
slot deadline. On terminal
use RX continuation and Admission reopening.

A clear assessment alone cannot complete a TX. Without valid PHYEND or
applicable busy evidence, unexpected DISABLED uses
the shared bounded check and Fault transition if the evidence remains absent.
Release the saved operation through the fault terminal. If the check finds
completion evidence, route it through the corresponding branch above.

Explicit stops use their saved stop kind and the explicit stop executor. Nordic
`nrf_802154_trx_transmit_frame` arms hardware TX and `irq_handler_phyend`
finishes it through `nrf_802154_trx_transmit_frame_transmitted`, without
a start-to-completion watchdog.

#### ACK drain candidates

**Window admission.** In NORMAL dispatch, the shared ACK-candidate resolver for `ack_rx` and
`ack_drain` uses `R:PollResponse.after_ack` only for a matching ACK. Open the
remaining window on the TX channel only if Frame Pending is set, the TX was a
Data Request, and the settings generation pinned at ACK END has
`rx_on_when_idle=false`. Use RX continuation after a terminal, whether or not a new window opens.
An opened window uses captured ACK END for its deadline and follows Window expiry.
For each response arm, including continuation after a frame or immediate ACK,
recheck the deadline immediately before RXEN. If setup crossed the cutoff,
promote any deferred renewal and continue from quiescence without launching
the expired arm.

**Sender ACK timing.** A reserved candidate can claim ownership only with
ADDRESS validated by Capture freshness and strictly before the sender's programmed cutoff (TX PHYEND
+ 887 µs). TIMER3 may service that cutoff at equality or later. The candidate
can succeed only if RX END validated by Capture freshness minus the 23 µs pipeline delay is strictly
before TX PHYEND + 864 µs. Corrected END at equality or later fails the
attempt, as does absent END on unowned cutoff. Use the same predicates
at RADIO or TIMER3 service.

NORMAL dispatch uses the same candidate decision whether END or DISABLED
wakes it first. Once END is serviced, verify DISABLED within that dispatch
or take the fault path. Only cutoff service can enter `ack_drain`, when a
qualified candidate still awaits END. Apply Close commitment and
`R:commit_boundary` at the cutoff or reuse the existing close record. A quiet wait closes without relying on a later
RADIO latch. If an ineligible ADDRESS already produced END→DISABLE
before read (1), discard that candidate, consume DISABLED once and
retry or report no_ack at verified quiescence. An explicit stop
retires the sender cutoff and
reports no_ack without resolving the candidate.
Nordic `nrf_802154_trx_receive_ack_received` routes parse or match failure to
`on_bad_ack`. `nrf_802154_trx_receive_ack_crcerror` routes CRC failure to the
same handler. It exits RX_ACK and reports an invalid ACK. Explicit abort and fault
use saved-owner results.

| Candidate | NORMAL dispatch at cutoff or DISABLED |
| --- | --- |
| Matching legacy ACK, good FCS and timely corrected END | Accepts once and apply Window admission. Arm a live response cutoff per Deadline arming. |
| Wrong DSN | Consumes the attempt. Retry if budget remains, using `R:Radio.begin_backoff` when randomized. Otherwise report no_ack. |
| Malformed ACK or non-ACK frame | Same attempt-consuming decision as wrong DSN. |
| Bad FCS | Same attempt-consuming decision as wrong DSN. |
| None or corrected END at or after cutoff | At cutoff without an owner, consume the expiry close record, including any saved DISABLED, and take the no-ACK retry or terminal at verified quiescence. A DISABLED arriving after the first read belongs to this same close. The candidate resolver consumes the expiry record without taking another boundary. A pre-cutoff owner retains END through DISABLED under Sender ACK timing. A late corrected END then takes the same no-ACK retry or terminal. |

### 4. Entry points × phases

Read each call’s ordered guards before its phase cell. A bare Run or Busy
cell uses the row’s common behavior. Serialize foreground calls. The
owned check compares the handle with the installed owner under the mask.
An enabled check is logical and applies even if RADIO is physically off.
The quarantined column routes the installed disabled owner through
software only. Preserve the packet DMA buffer and the quarantine state.
Disabled settings access uses committed settings memory only.
Timed TX/RX remains unsupported.

Rows marked Settle due deadlines first run the NORMAL prologue. The
masked owner check prevents peripheral access through an unowned or
disabled handle. After settlement, use the resolved phase and logical
owners. An unowned or disabled prologue is inert. Wrapper calls settle
through each state, submission, time or poll dispatch. Stateless
helpers on supplied values do not address a radio handle. Notify swap
commits before settlement.
Sleep, channel retune, Disable and Deinit do not run a prologue.
The `queued_event_count` diagnostic samples only the masked FIFO depth.
It shares the prologue exemption with Init and absent optional slots.
Deinit checks Consumer backlog first. An explicit stop directly uses
the explicit stop executor, while Receive matching a committed or outstanding channel runs NORMAL dispatch.
**Init admission.** Under the mask, check the singleton routing slot
and quarantine state before validation, hardware access or any access to
the supplied handle storage. An occupied or quarantined slot returns Busy
without a prologue, including when the address is the quarantined owner's
address. Chip reset clears quarantine. Only a free, nonquarantined slot
may validate and initialize a new disabled owner.

**Init retirement.** Install the disabled routing owner with sealed
publication before starting radio-owned producers. Before publishing
verified off, retire those started by Init. The shared HFCLK request
follows the HF crystal startup row. For TEMP, issue STOP and verify with a
bounded wait, then clear DATARDY. For RNG, use the bounded STOP and
VALRDY sequence in RNG retirement. Use these checks on all exits after
starting the producer, including timeout or fallback. The initial TEMP
read does not by itself establish verified retirement. Follow the
interrupt isolation and disabled wake steps in Lifecycle teardown before
returning. If retirement cannot be verified, return HardwareFault
with publication sealed and the owner, routing and DMA storage
quarantined. The caller must keep the installed handle and all its
storage stationary until chip reset, even though Init returned an
error. Deinit then follows its disabled quarantine guard. Every other
Init error leaves no new owner installed. If Init fails after installing
a provisional owner and cleanup verifies retirement, release the
provisional owner before returning the original error. Busy leaves
the incumbent untouched. Successful Init returns in verified off with
both vectors disabled, and backlog-free Deinit can release without
hardware teardown.

Any null optional slot bypasses driver dispatch and returns Unsupported from the portable wrapper without changing state. On nRF this applies to `I:receive_at`. Timing capability stays clear.

**Admission decision tick.** Receive, TX, ED and standalone CCA hold one
mask across the NORMAL prologue where applicable, guards and commitment,
including both reads for a new close. Use the final TIMER3 sample as
the admission decision tick, including for a renewal or admission with
no new close. The later DISABLED and ADDRESS reads determine only
hardware ownership. Time elapsed between the sample and either read,
or between the sample and a logical renewal, leaves the admission decision
unchanged. If the sample finds the response cutoff due, settle it through
NORMAL and reassess the guards before committing a close. If a departure
earlier in this call left a saved replacement, apply Window expiry only;
the pended dispatch arms the replacement. A cutoff at or before the tick takes natural expiry and
promotion. A live window at that tick can be renewed or retired early
per the entry rule. A cutoff that becomes due after that decision is
handled by the next dispatch if its generation remains live. Never
repeat the reads of an already committed close.

**Operation admission.** For TX, ED and standalone CCA, run the entry
guards and NORMAL prologue, then validate the arguments. Under the same
mask, preflight the operation, frame and immediate ACK owners and the FIFO
reservation. Check already-latched current-arm ADDRESS using Owned END.
A capture-validation fault returns Aborted via Close fault return before
further hardware access or admission. Otherwise return Busy without accepting work if this preflight sees a frame or
ACK owner or a conflicting operation or reservation. An idle-only stop
with no saved owner or target can accept the new target.

After preflight, sample the Admission decision tick and apply Close
commitment for a new handoff. If expiry changes the resolved context,
repeat the guards before committing against that context. If ADDRESS
arrived since preflight and is owned at the ADDRESS ownership read,
admit the operation as the sole saved continuation behind that frame.
Complete the frame and any owed ACK normally per Close commitment,
then run the admitted operation. The frame result or applicable RX outcome and the operation
terminal have independent reservations. An ADDRESS after the ownership
read is dropped per `R:commit_boundary` and the operation proceeds after
quiescence. If an active close already exists, use its saved record.
A fault before admission leaves the new operation unaccepted.

Successful admission retires a still-live response window per Window
expiry after close checks pass. The admitted operation has priority over
the outstanding explicit receive request, including a newly promoted
renewal. Reconcile old END and DISABLED before reusing hardware.

**Receive admission.** Apply this ordered rule under the mask in every phase.

0. If the handle is unowned, return InvalidState.
1. If the owner is logically disabled, including after Disable or a
   fault, return InvalidState before examining operation or channel
   state. Do not dispatch, publish an RX request or touch hardware.
2. Check whether a TERM_NONE operation is admitted or in flight.
   TX, ED and standalone CCA all hold this guard, including while
   waiting behind retained stopping. Return Busy on any
   requested channel before validation of the channel, dispatching a
   prologue or choosing an explicit stop. Do not consume DISABLED or change ownership.
3. With the operation guard clear, validate the channel and classify
   against the committed logical RX context before judging any deadline.
   An installed response window stays committed to its TX channel
   until NORMAL expiry, including at a due but unserviced cutoff.
   Otherwise use the ordinary or retained RX channel, or the persistent
   requested channel when there is no receiver context. Compare the
   requested channel with both this committed channel and any outstanding
   explicit request channel. Only a mismatch with both is a retune.
   It takes direct Mode stop. A match takes the NORMAL prologue and
   returns Aborted on fault. NORMAL dispatch cannot admit a new
   TERM_NONE operation.
4. After NORMAL settlement, use Admission decision tick to check whether
   the requested channel is the live response window’s own channel. In that case apply Window
   renewal, including while an ACK is owed. Otherwise return Busy if an
   immediate ACK still owns RX or a frame still owns an RX context on a
   different channel. Only after this guard may a matching outstanding
   request on another channel renew behind the live window.
5. Renew or record the explicit request using the resolved state.
   Same-channel ordinary RX, including buffer-missing RX, preserves
   owner, DMA and captures without another RXEN or START, including
   with ADDRESS owned or END draining. A committed policy close
   finishes before the renewed request arms. If NORMAL expiry moved
   the logical channel, the matching entry remains non-preemptive.
   Keep any qualified pre-cutoff owner through END and its ACK. Apply
   the request after quiescence through RX continuation. If the resolved
   receiver must close, stage the renewal and use a natural handoff.
   Publish the new request only when the handoff succeeds. If that close
   faults after successful NORMAL settlement, return Aborted without
   recording the staged request. Fault transition retires the old
   request and preserves any owed results.

Nordic `nrf_802154_core_receive` and ESP-IDF `ieee802154_receive`
preserve unchanged RX. For a preemptive receive, Nordic
`nrf_802154_receive` requests TERM_802154 and can abort TX.
This driver keeps the admitted operation exclusive. See #50 for
the OpenThread Receive guard.

Configure publishes one validated settings transaction. Init selects
the initial channel and later retunes go through receive. Settings and source-match edits
are synchronous in any owned phase (`R:Radio.configure`, `R:Radio.publish_rx_settings`).
**Idle-policy change.** `R:Radio.apply_settings_change` runs this
ordered transaction under the mask for Configure and SetRxOnWhenIdle:

1. Stage and validate the requested edit against the committed generation.
   This includes power and threshold validation, NoSpace on a full source
   table, and NotFound on removal of a missing entry. Configure stages one
   channel-free bundle.
2. Take the TIMER3 publication tick while an RX arm can capture END. Use
   CC3 to keep any older generation that arm still needs. Publication
   while no RX arm is live simply sets the generation for the next arm.
3. Publish the staged generation once. Settings pin chooses the whole
   generation from the captured END tick, even when END or DISABLED is
   still hidden at publication. An already derived ACK keeps its saved
   disposition.
4. On true→false, retire requests through the saved sequence even when
   RX is temporarily off or used by another operation.
5. **Exact capture-time selection.** The setter publishes and returns without
   waiting for an in-flight frame or its ACK. Schedule an eligible idle
   close for the resolver. Use Close commitment to retain an owned frame
   and bound any required DISABLED check. A later missed DISABLED is
   reported through the sticky fault and any saved terminal. It does
   not change the setter's return value or undo the publication. A fault in NORMAL or the bounded history wait can still prevent
   publication.
6. Follow RX continuation under the new settings. Earned response windows
   keep their cutoff. An explicit `set_rx_on_when_idle(true)` requests
   startup even if true is already committed. In enabled idle, arm on
   the last receive channel. A live backoff slot keeps its deadline.
   Configure requests startup for false→true only. A subsequent true
   cannot restore a retired request.

Fault teardown independently retires its owners. Nordic
`nrf_802154_pib_rx_on_when_idle_set` stores the policy value, and
`nrf_802154_trx_transmit_frame_transmitted` (without sender ACK) and
`nrf_802154_trx_transmit_ack_transmitted` call `switch_to_idle`, which
selects RX or Sleep from the current policy without replaying a pre-TX or pre-ACK Receive request. `nrf_802154_core_receive`
does not stage a renewal across an unchanged RX or TX_ACK state.
OpenThread `SubMac::SetRxOnWhenIdle` forwards policy independently of
`SubMac::Receive` and `SubMac::Sleep`. When its RCP TX completion needs to
switch RX channels, `SubMac::HandleTransmitDone` issues a fresh Receive.
These paths provide policy-driven RX after completion without a saved explicit request to revive.
[OpenThread SubMac](https://github.com/openthread/openthread/blob/main/src/core/mac/sub_mac.cpp).
An unchanged false write preserves all RX state, including explicit one-shot receive().
Configure still publishes its other settings in that case.
An earned response window keeps its lifetime and sender ACK RX
remains operation-owned. Other setters publish settings without changing the arm (`R:Radio.publish_rx_settings`). The idle-policy
vtable entry and Configure return Aborted if NORMAL or the history wait
faults before publication. A close fault after publication is pollable
with the saved results. It does not invalidate the successful setter return.

**Lifecycle admission.** Disable has no backlog guard or prologue. An
enabled handle goes straight to Lifecycle teardown. A fault during its
close or teardown returns HardwareFault with the results pollable.
Disable when logically disabled is a no-op success without hardware
access, including after a fault with unresolved retirement. It preserves
the publication seal, pollable results and sticky record. Only a
successful teardown certifies physical retirement. The original fault
record reports a retirement failure, and Enable returns HardwareFault
if retirement verification fails or quarantine is set. Deinit checks
Deinit guard first. If Enable's own prologue faults, return HardwareFault
with the handle Disabled. A subsequent Enable can start a new lifecycle
after verification if the owner is outside quarantine. A quarantined
owner keeps returning HardwareFault without hardware access.
If settlement succeeds and the handle was already enabled, Enable succeeds
without starting or resetting a lifecycle. Otherwise apply Enable
verification before opening admission.

**In-place RSSI.** Every phase applies this ordered admission predicate
under the RADIO/TIMER3 mask:

1. Return InvalidState if unowned, then if logically disabled.
2. Run the NORMAL prologue. Return Aborted on fault. An immediate ACK in
   progress or a committed close that owns a frame returns Busy: an RX
   owner retained in natural stopping, or a sender ACK candidate that the
   cutoff retained in `ack_drain`.
3. Return InvalidState without testing a latched ADDRESS when there is
   no packet RX arm (including an unowned stop), when the arm has no RX
   reservation, or for sender ACK RX in `ack_rx`.
   The sender ACK wait is never eligible for a sample, owned or not.
   Nordic `nrf_802154_core_rssi_measure` likewise measures only in
   RADIO_STATE_RX, not in its RADIO_STATE_RX_ACK wait.
4. Qualify a latched ADDRESS through Owned END for the current context.
   A capture-validation fault returns Aborted via Close fault return. A
   qualified frame owner returns Busy. An ADDRESS outside a live response
   window returns InvalidState.
5. Require a resolved logical context of ordinary RX, a live
   response window or listening backoff, with an enabled physical packet RX
   arm for the same context and generation and hardware in Rx or RxIdle.
   A retired arm is ineligible even if its channel matches the new context.
   Update RX settle for the eligible arm and require its `settled` flag. If
   RXREADY capture validation faults, return Aborted via Close fault return
   before any sampling. Otherwise return InvalidState for an unmet
   prerequisite.
6. Use RSSI sample ownership to take the diagnostic sample. The call uses
   no RX handoff, new IRQ arm or protocol deadline.

**RX settle.** A new packet RX arm clears `settled` before RXEN. Until
the flag is set, use current-arm RXREADY validated by Capture freshness
and require at least 16 TIMER3 ticks from its CC0 capture. Latch `settled`
under the mask when proven. Subsequent RSSI admission uses the latched
decision without recomputing modular age. Housekeeping retains the decision
until the old arm retires. A fresh arm takes new RXREADY evidence and must
prove its own settle interval.

**RSSI sample ownership.** The packet path keeps the ADDRESS→RSSISTART
shortcut as Nordic does in SHORTS_RX. For packet metadata, read and save
RSSISAMPLE directly for the frame at END service, or at DISABLED when
completing that saved END before the next arm. Packet metadata never
tests, clears or waits on RSSIEND. Clearing the event alone leaves the
RSSISAMPLE register untouched.

PS v1.11 §6.20 gives a typical RSSI sampling period of 0.25 µs from
RSSISTART, distinct from the 15 µs signal settle time. From ADDRESS at
SFD end, the PHR alone takes 32 µs on air at 250 kbit/s, before payload
and RX END pipeline delay. The packet measurement therefore has ample
time to complete before END at the cited timing. The timing table
records the PS gap for overlapping RSSISTART tasks.

For a diagnostic, after the initial eligibility check clear RSSIEND
and recheck logical RX eligibility and the current-arm ADDRESS latch
before issuing software RSSISTART. An ADDRESS between the initial
check and the clear makes this recheck return Busy without another
start. Its packet sample is still available at END even if the
diagnostic cleared the event. Otherwise issue RSSISTART, poll RSSIEND
with the shared CPU bound, read RSSISAMPLE, then recheck ADDRESS
before returning a dBm value. Attribute the sample to the diagnostic
only while ADDRESS remained clear through that read. Discard the
sample and return Busy if ADDRESS latched after the last pre-start
check, including in the narrow check-to-task interval. An ADDRESS
after the task starts requests the later packet sample. If it wins
just before the software task, the overlapping software request also
belongs to the packet, and its result cannot be returned to the
diagnostic caller. RSSISAMPLE at packet END is the in-frame sample
under the overlap requirement in the timing table.

If ADDRESS latches while waiting, the diagnostic can abandon the wait
with Busy. Before faulting on RSSIEND timeout, recheck ADDRESS once
more to distinguish a packet collision. With no collision, a failed
bound uses Fault transition and returns Aborted. The diagnostic never
consumes ADDRESS, END or DISABLED and never stops packet RSSI.

Nordic `nrf_802154_core_rssi_measure` requires RADIO_STATE_RX.
`nrf_802154_trx_rssi_measure` checks hardware RX state, observes the 15 µs
settle interval, clears RSSIEND and triggers RSSISTART.
`nrf_802154_core_last_rssi_measurement_get` uses `rssi_measurement_wait` under
its critical section and reads the sample through
`nrf_802154_trx_rssi_last_sample_get`. `nrf_802154_rssi_last_get` returns
NRF_802154_RSSI_INVALID when no result exists. This driver uses captured
settle evidence at admission and bounds the RSSIEND spin with the shared CPU loop bound.

PS means [nRF52840 Product Specification v1.11](https://docs.nordicsemi.com/r/bundle/ps_nrf52840).
IEEE means [IEEE Std 802.15.4-2006](https://standards.ieee.org/ieee/802.15.4/3582/).
**Settle due deadlines first.** NORMAL dispatch is the single resolver
mode for both ISRs and the entries marked with this prologue. Receive checks the exclusive operation guard
before any dispatch. After Notify

the running counter directly. Apply current-attempt PHYEND precedence
before normal TX CCA settlement. Import live measurement origins and apply

expiry effect. Initiate any necessary hardware handoff in this dispatch.
A physical phase that has already begun may still own DISABLED or ACK

| --- | --- |

**Masked resolver.** Only `R:Radio.resolve` performs natural completion,

Apply RX continuation on the logical state. For each

**Close fault return.** A fault in NORMAL settlement uses Prologue fault
return, including a due close. A capture-validation fault in the body of
a fallible operation or RSSI call after NORMAL enters Fault transition
and returns Aborted. Stop further hardware access and admission after
fault teardown. This takes precedence over Busy and InvalidState,
including at operation preflight, RSSI ADDRESS qualification and

or operation submission before accepting new work. Either policy setter
can return Aborted on a NORMAL prologue or history wait fault before
publication. A close after publication exposes its sticky fault and
saved results without changing that return value.
A failed renewal publishes no new request. Fault transition retires the
old request. Disable and Deinit return
HardwareFault from a fault at their own explicit close boundary. Deinit
retains routing. Poll drain returns the sticky fault on that call.

**Blocking wait fault exit.** Each iteration of receive_blocking and
of the admission and completion waits for transmit_blocking,
energy_scan_blocking and cca_blocking checks state and fault_pending
before elapsed time. Recheck after now_us before using its elapsed
value or making a submission, because now_us can discover a fault.

Before returning InvalidState for Disabled or a submission refusal,
read fault_pending. A pending fault returns Aborted without polling,
including at the first state call and after a submission race. A
Disabled entry or InvalidState refusal with no fault returns
InvalidState. An ongoing wait also ends if Disabled is observed. If
there is already an admitted operation, return Aborted and leave
its terminal pollable. A pending fault stops retries and timed waiting even if an accepted
operation's terminal is queued. Return Aborted without dequeuing it.
The caller drains the fault and any terminal in normal order. Ordinary
polling while fault-free can return the matching result as usual.
The wrapper must leave the fault record and unrelated terminal
available on fault exit, regardless of the optional handler. Use the
fault-preserving poll mode in every admission and completion loop.
Under the same mask as the dequeue, run NORMAL then check the sticky
record and enabled state before taking any event. Return null without
consuming anything when a fault is pending or the radio is disabled.
The wrapper rechecks state and fault_pending after that null.

Aborted is the portable fault error for all four wrappers. HardwareFault
stays a driver lifecycle result. The non-consuming query and the pollable
fault record expose the hardware reason.

**Prologue fault return.** A dispatched call whose own prologue enters
Fault transition stops hardware work after that teardown. It never touches a
retired producer or starts a new lifecycle in the same call. Poll still
drains results and set_notify has already completed the hook swap. An ISR exits ordinary dispatch and preserves the fault wake.
Use the result below, based on the call's return type:

| Public call category | Return after its own prologue faults |
| --- | --- |
| Enable | HardwareFault. Keeps HAL Disabled. Only a later Enable may reopen admission. |

| Portable blocking wrappers | No independent prologue. Uses fault_pending before Disabled or InvalidState refusal and during the wait, including the first state call. A pending fault returns Aborted without polling. |

**Deadline arming.** `R:Radio.arm_at` arms CC1 protocol deadlines and
records the tick in `deadline`. `R:Radio.program_compare` programs any
compare channel: CC1 through `arm_at`, CC5 for TEMP service and CC0 for

current counter. CC5 rearm never writes, clears or masks CC1 and does not
retire a protocol or housekeeping arm. A deadline is due at equality or
later, using wrap-safe TIMER3 order (`P:tick_reached`). This applies to
response and sender ACK cutoffs, backoff slots, ED and CCA result checks, and
enabled CC5 service. Capture housekeeping uses its own CC1 latch mechanism
for arming, prologue settlement and IRQ dispatch. Captured eligibility is
separate (Owned END and Sender ACK timing). Immediate ACK launch requires a
tick strictly before its arm margin. An already-due deadline is pended
immediately, including zero-delay slots and deadlines carried across a stop.
Service compares the live record with the counter, then retires only that
channel's deadline (`R:Radio.disarm_deadline` for CC1). The record is
cleared before another arm is selected on that channel. This includes a
response cutoff whose frame or ACK still owns completion. A compare in the
past cannot be relied on to wake service.

**Hardware progress.** PS v1.11 §6.20 and its electrical timing tables specify RADIO

Owned RX closes use the commit-time watchdog below. Other RADIO state changes

loop bound so a stopped TIMER3 cannot extend a wait. A failed check while enabled uses Fault transition or Faults within teardown when a teardown is active. Before enabling,
use Enable verification. Nordic `nrf_802154_trx.c:wait_until_radio_is_disabled` spins up

**Capture handoff.** After Close commitment for normal phase change, Sleep, retune, Disable,

Apply the same order to early POWER recovery with the retained evidence
available before reset.

**Capture freshness.** With the old route retired and the next producer
stopped, clear/read back its RADIO latch. Read the 32-bit 1 MHz TIMER3
counter as arm tick `A`, write the full CC word to `A -% 1`, and enable the
capture route before exposing the producer. Keep capture-channel compare
IRQs, shortcuts and launch routes off while the channel is a capture.
Under the IRQ and masked-foreground service assumption, the counter
cannot revisit the sentinel during the live arm. A real capture then has
`(CC -% A) <= (now -% A)`, using a counter sample after reading CC.
Apply the same modular u32 test across raw rollover within a valid arm.
A full cycle of the same arm exceeds the assumption and carries
no freshness guarantee.

When a current-arm RADIO latch is observed, read its CC through

to one 16 MHz period (62.5 ns) of PPI synchronization. The complete
latch-to-readable-CC bound is an open question.

**Capture housekeeping.** An ordinary reserved RX arm uses CC1 as a
dedicated one-shot hardware-latch deadline while no protocol deadline owns
CC1. With its IRQ masked, program CC1 to the current counter plus 2^31 µs
modulo 2^32, then clear and read back the old compare event. Programming
and clearing complete before the half-range match. Set the `housekeeping`
role flag and enable the IRQ (`R:Radio.start_rx`). Use the hardware
compare event as the deadline evidence. A fresh arm at a given raw tick
has no latch. Once the compare fires, the latch survives delayed service
within the service assumption, including raw rollover during a valid arm.

Both the prologue and CC1 IRQ path use the same role flag and latch
check under the mask. Retire the consumed role and clear the event once
before continuing. If a transition ends the RX arm before service, cancel
its role and clear its latch before assigning CC1 to another deadline.
No housekeeping path uses `arm_at` or signed due-time order.

NORMAL dispatch handles expiry directly. An ineligible or retired RX
arm cancels the compare. If service observes an owed immediate ACK from
that arm, skip the prime. A stale compare after handoff leaves the
immediate ACK routes and capture CCs intact.

| Housekeeping state | NORMAL dispatch |
| --- | --- |
| No ADDRESS owner | Uses Close commitment for a natural RX close and follow Capture handoff. Uses `R:commit_boundary` for an owner that arrives during handoff. |
| ADDRESS owner at service | Skips the prime, including when an immediate ACK is owed. Owner completion retires the arm. Preserves the ACK launch and live capture CCs. |

capture CC. Buffer-missing RX has no capture routes to prime. The compare latch establishes expiry. NORMAL dispatch from foreground or IRQ relies on the
IRQ and masked-foreground service assumption for capture freshness.

validated PHYEND fallback (subtract known on-air length after SFD) when

the saved terminal, also untimed, per Fault timestamps. Ramp-up alone
proves no start. A normal TX terminal with no on-air attempt retains
the existing zero timestamp convention.

**Measurement origin.** Before RXEN, clear the prior start latch, install
PPI 19 to capture RXREADY→CC0 for TX CCA or standalone CCA, or READY→CC0
for ED. Keep the CC0 compare IRQ and ACK launch route inactive. The
start latch cleared before RXEN identifies the event. Apply Capture freshness
before the prologue imports CC0 once for that arm and derives the cutoff from its validated tick
plus the duration, regardless of which dispatch first sees the latch. Use 128 µs for CCA and the selected
number of 128 µs ED samples (PS v1.11 §6.20). Record the derived deadline
once before retiring the start latch. A matching start IRQ that arrives
later cannot replace or recreate it, even after the saved result retires the compare. If still in the future, arm CC1 per
Deadline arming. If already due, NORMAL dispatch settles the result or
runs the bounded hardware check. READY→EDSTART and RXREADY→CCASTART are
the sole start producers. No entry or handler issues a second task. Retire
PPI 19 before CC0 reuse.

**Saved measurement result.** ED, standalone CCA and TX CCA use the same
optional record, `R:Radio.measurement_result`. Each measurement arm starts
with an empty record, and `R:Radio.retire_arm` clears it. Before
clearing EDEND, save the measured peak from EDSAMPLE using the ED result
conversion. Before clearing CCAIDLE or CCABUSY, save clear or busy, respectively.
Only a current-arm latch can fill the record, in NORMAL dispatch from an
ISR or foreground prologue. A direct explicit stop leaves the latch for its executor. Retire the measurement compare when the result is saved.
Keep the result for the same arm through quiescence, independent of
the compare. If standalone CCA is clear, the resolver requests DISABLE
once. EDEND and CCABUSY already request DISABLE through their shortcuts.

At expiry or DISABLED-first service, the resolver looks boundedly for a
current-arm result if it has no saved evidence. Once EDEND, CCAIDLE or
CCABUSY is serviced for standalone ED or CCA, verify DISABLED in the same
dispatch even though the result is already saved. Either failed check
enters Fault transition. A stale saved result cannot complete a new arm.
Retire the arm before publishing its terminal once.

When PHYEND is absent, TX CCA uses the same record for measurement
settlement. Clear preserves TX progression. Busy charges Busy assessment
once and verifies DISABLED in the same dispatch. A failed busy close
preserves any earned terminal for the explicit stop executor, which otherwise aborts without
charging unserviced CCABUSY. Valid PHYEND takes TX attempt completion
without requiring a saved clear result.

Slot creation captures the running counter at the decision. Sender ACK and
response cutoffs use TX PHYEND and ACK END respectively.

**Producer retirement.** Use Lifecycle teardown. Revoke launches first, retain
active captures through RADIO quiescence and reconciliation. Verify retirement
and isolate IRQs, or quarantine, before publishing saved results.
Use Wake preservation before each hardware-pending clear and after the last clear.

**Failed retirement.** A failed STOP check requires a bounded reset and
verification before reuse. RADIO uses POWER down and reset, following Nordic
`nrf_802154_trx.c:nrf_802154_trx_disable` and its `nrf_radio_reset` POWER
sequence. Preserve qualified evidence before reset and keep TIMER capture
routes active until power-down stops RADIO. TIMER3 repeats the shared TIMER3 retirement sequence after its
launch routes are revoked, with both compare records cleared. TEMP requires
proven STOP quiescence and a cleared DATARDY before a fresh START. Clear the
started-in-this-lifecycle flag on retirement and set it only with that new
START. Ignore DATARDY until the flag is set. RNG retirement likewise requires a
verified STOP before reuse.

Keep an unverified producer isolated, and never release potentially live DMA.
Use Enable verification before producer reuse in a nonquarantined lifecycle.
Restore configuration and run Timer start before opening admission, regardless
of unread results. A teardown that encounters a failure follows steps 4–6.
If retirement remains unverified after bounded reset, quarantine the
installed owner and its DMA storage until chip reset. Init admission and
Deinit guard enforce quarantine independently of the pollable fault.

### 7. Interface consumer trace

The OpenThread reference is the ESP-IDF checkout's `openthread/platform/radio.h`.
HAL synchronous faults expose Disabled through state() before returning.
One terminal per operation and Synchronous Disable make fault terminals available to the consumer. Platform callback,
state and refusal handling belong to #50.

#### Interface guarantees

| Guarantee | Interface boundary |
| --- | --- |
| One terminal per operation | Each admitted TX/ED/CCA produces one reserved FIFO terminal, including on fault. Terminal commitment preserves this guarantee. In-place RSSI returns synchronously without reserving a terminal. Sticky fault coalesces fault reports outside the FIFO. |
| Synchronous Disable | Portable `I:VTable.disable` is synchronous. On success state() is Disabled, publication is sealed until a successful Enable and every accepted operation’s terminal remains pollable. The sole publication exception while sealed is a sticky fault diagnostic from failed Enable startup. That attempt publishes no FIFO event. Success certifies physical retirement only when the call performed teardown. An already-disabled no-op after a fault preserves the seal and results, with retirement failure reported through the fault record and Enable verification. Disables does not return Busy for an outstanding operation or ACK. Teardown failure leaves saved results available through the hardware fault path. |
| Fault observation | The portable `I:VTable.fault_pending` reports pending, reason and count without consuming events. Blocking wait fault exit uses it before refusal or fault return. The vtable poll mode checks for a sticky fault after the NORMAL prologue and before dequeue under the same mask. This covers a fault becoming visible after the wrapper’s last query as well as one discovered by poll itself. In preserving mode a fault or disabled state leaves every queued result for the caller. |
| Init error ownership | Init HardwareFault retains routing and quarantines the handle. The caller keeps that storage stationary until chip reset. Other Init errors leave no new owner installed, so the caller may unwind its attempted handle. Busy preserves any incumbent. |
| Deinit backlog | Deinit checks Consumer backlog first. Enabled Deinit runs a direct explicit teardown and rechecks backlog. A backlog-free disabled owner releases routing only if prior retirement was verified. Unverified retirement returns HardwareFault and quarantines routing and storage until chip reset. Neither disabled branch accesses hardware. Busy and HardwareFault preserve routing. A fault during explicit teardown returns HardwareFault after the wake. |
| Ordered entry guards | Applies the ordered entry guards before admitting work. Receive on an unowned or disabled handle returns InvalidState before the operation or channel checks. Applies Prologue fault return in entries that run NORMAL settlement. TX/ED/CCA may be Busy at admission. Occupied Init returns Busy without settling the incumbent. Deinit may be Busy for unread results. Setters never return Busy. Enables uses Lifecycle admission and Enable verification. |

#### Zigbee and capture

| Consumer step | Interface calls and events |
| --- | --- |
| Coordinator chooses channel and starts PAN | Enable; retry Busy for ED/CCA (Ordered entry guards) and drain their terminals (One terminal per operation). Commits PAN, addresses, coordinator and idle policy synchronously, then admit receive. Consumes same-PAN destinationless data and command frames; MAC builds beacons and handles association (`I:VTable`, `H:Header.filter`). |
| Coordinator/router serves a sleepy child | Update source match synchronously (Ordered entry guards), then admit the downlink through the Busy-gated transmit path and consume its attempt and terminal events. Reads the child Data Request RX indication with ACK and Pending flags; MAC owns indirect expiration and security (`I:add_src_match`, `S:Table.frame_pending`, `R:Radio.publish_pending_rx`). |
| Router discovers and joins, then forwards | Hop via receive or scan first. Retry ED if Busy. Transmit discovery/association commands and set addresses and source match synchronously. Stay in RX with idle policy true (`R:Dispatch.receive`, `R:Radio.take_event`). |
| Sleepy end device joins, polls and sleeps | Sets idle RX false and use sleep-to-TX for a Data Request. Normal ACK completion applies Window admission. A sender ACK fault yields no_ack and no window. A Receive on the live window channel uses Window renewal. MAC rejection of a delivered frame leaves the poll window open for the reply. A qualifying downlink follows Owned END and RX continuation. |
| Sniffer starts, hops and stops | Sets promiscuous mode and optionally bad-FCS delivery, then receive on each channel. A hop aborts undelivered old-channel RX or abandons its ACK and delivers the accepted frame. Drains these notifications in FIFO order. Copies RX/FCS, quality, RSSI, channel, timestamp and CRC validity into capture output. Track coalesced overrun, which marks where the first unread episode of capture without a FIFO slot began; later losses fold into it until poll reads it, so frames lost after that point carry no marker of their own. Also track aborted RX and radio fault events. At shutdown use Synchronous Disable, drain, then Deinit backlog. Passive capture uses RX only (`R:Dispatch.receive`, `R:Radio.take_event`). |

#### Contract across consumers

| Check | Behavior |
| --- | --- |
| Software ACK fallback | With `I:Capabilities.ack_timeout=false`, publish sent after the on-air attempt, with no ACK in the terminal. For ACK-requesting frames, be ready to receive on the TX channel in time for an immediate ACK at aTurnaroundTime (12 symbols, IEEE 802.15.4-2006 §§6.4.1 and 7.5.6.4.2), independent of polling. Admit a received ACK frame through the ordinary RX type filter in this reply mode and deliver it as an ordinary RX event after the queued tx_done. Broadcast and other no-AR TX keep the normal receive continuation without redirecting RX to the TX channel (`I:VTable.transmit`). The consumer owns matching, the deadline and retry. This driver offloads ACK timing and retries. |
| Correlation | Each admitted TX/ED/CCA holds the one reservation until its terminal event is read, so a new one cannot inherit an old terminal. Correlate every terminal to its accepted request (One terminal per operation). `tx_started.attempt` is local to an accepted TX. RX has no request ID; use frame channel to distinguish hops (same-channel renewals provide no epoch), and `I:receive_blocking` returns the next queued RX. `R:EventReservation`, `R:Radio.take_event`. |
| Buffer lifetime | nRF copies TX before return, including a slice from the last poll; wrapper snapshots before any Busy drain. RX/ACK slices expire at next poll, so copy before any re-entrant poll, queueing to another thread or writing a deferred pcap record. OpenThread frame storage is covered under #50. `R:Dispatch.transmit`, `I:transmit_blocking`, `R:Radio.take_event`. |
| Event completeness | Reserves one FIFO terminal for each admitted TX/ED/CCA. RSSI returns one synchronous result. Fault transition records saved-owner results and updates the separate sticky fault, polled ahead of FIFO. Preserves operation terminals across lifecycle changes. |
| Notification | Mode stop and lifecycle teardown use Wake preservation. Enabled RADIO IRQ delivers a coalesced wake for saved progress or backlog. Teardown and disabled calls use direct delivery independent of the vectors. Notify swap checks both. Uses Poll drain until null, including the sticky fault before FIFO and the overrun marker before later events. RADIO and TIMER3 provide normal completion and retry wakes. Every wake request sets one `notify_pending` flag. The RADIO IRQ, or direct delivery while disabled, clears it before calling the hook once, so a FIFO backlog and new progress that overlap produce one wake (`R:Radio.request_event_notification`, `R:radio_interrupt`, `I:VTable.set_notify`). |
| Argument rules | TX and its ACK use TX channel, normal continuation uses requested RX channel. Validate channel, power, legacy ACK header and retry limit; ignore backoff count if CCA off. Timed TX/RX is unsupported. CCA uses Logical assessment channel after the final admission cutoff decision. ED has an explicit channel, and RSSI uses a settled arm for the resolved logical context. `R:Dispatch.transmit`, `R:Dispatch.cca`, `R:Dispatch.energy_scan`, `R:Dispatch.rssi`. |
| Unavailable | Before init and after deinit operations return InvalidState for valid supported requests. Disable is idempotent; unowned setter results follow the entry matrix, poll returns null, blocking calls reject disabled before timing (`R:Dispatch.state`, `R:Radio.require_enabled`). A disabled or unowned HAL Disable is a no-op without hardware access per Lifecycle admission. |
| Same meaning across ports | Successful standalone CCA true means clear in `I:Event.cca_done`, `R:Radio.service_measurement` and ESP `ieee802154.zig:Radio.cca` (inverts `Energy.busy`). ESP's `TxResult.cca_busy` names the busy outcome. ESP and nRF ordinary TX take MAC bytes without PHR/FCS, but ESP's security-aware call can construct the MIC, so a portable caller must not infer a shared security contract. |

## Prior art

- ESP 802.15.4 uses stationary singleton ownership, MAC bytes without FCS, explicit event clearing,
  immediate ACK handling and the same unslotted CSMA/ACK-wait principles. ESP
  `ieee802154.zig:Radio.receive` and `ieee802154.zig:Radio.transmit` use synchronous polling via
  `ieee802154_rx.zig:receive` and `ieee802154_tx.zig:transmit`. Its enhanced ACK ISR posts
  results into atomics, and it has security-aware RX/TX and enhanced ACKs. nRF places all phase
  progress in RADIO/TIMER3 plus foreground reconciliation, copies into a bounded async queue
  and leaves security to the stack.
  [ESP radio](../../port/espressif/esp/src/hal/radio/ieee802154.zig),
  [RX loop](../../port/espressif/esp/src/hal/radio/ieee802154_rx.zig),
  [TX loop](../../port/espressif/esp/src/hal/radio/ieee802154_tx.zig).
- ESP-NOW's `espnow_session.zig:Session.send`, `espnow_session.zig:Session.poll_delivery` and `espnow_session.zig:Session.deinit`
  reserve an asynchronous completion independently of receive overflow and keep the singleton
  while a callback can arrive. nRF reuses the reservation/poll pattern and adds attempt events in a
  shared FIFO. This driver adopts ESP-NOW’s Busy-until-completed rule and also waits for unread
  events, including RX and overrun. nRF owns reset and IRQ routing. Its shared fault path forces quiescence after a failed bounded state check.
  [ESP-NOW session](../../port/espressif/esp/src/hal/radio/espnow_session.zig).
- Nordic `nrf_802154_csma_ca.c` schedules backoff in `random_backoff_start` and charges a
  refused `frame_transmit` in `channel_busy`. `nrf_802154_core.c` defines
  `can_terminate_current_operation`, `current_operation_terminate` and
  `operation_terminated_notify`. Public admission and settings entry points are in
  `nrf_802154.c`. `nrf_802154_pan_id_set`, `nrf_802154_promiscuous_set` and
  `nrf_802154_rx_on_when_idle_set` publish settings independently of operation admission.
  `nrf_802154_channel_set` has a separate channel update path.
  `nrf_802154_trx.c:nrf_802154_trx_disable` calls `nrf_radio_reset`, which cycles RADIO
  POWER on supported chips. `wait_until_radio_is_disabled` bounds a RADIO-state wait and treats
  violation as a fault. `transmit_frame_abort` replaces the TX shortcut mask
  before requesting hardware disable. ESP-IDF `esp_ieee802154_dev.c:ieee802154_transmit`
  reports busy for a CCA request when RX or ACK owns the radio. Its
  `ieee802154_finish_receive_at` preserves SFD-owned RX at scheduled expiry, and
  `ieee802154_receive` keeps an unchanged RX configuration armed. OpenThread
  `sub_mac.cpp:SubMac::StartTimerForBackoff` chooses Receive on the TX channel or Sleep.
  [Nordic driver sources](https://github.com/zephyrproject-rtos/hal_nordic/tree/master/drivers/nrf_802154/driver/src),
  [ESP-IDF driver](https://github.com/espressif/esp-idf/blob/master/components/ieee802154/driver/esp_ieee802154_dev.c),
  [OpenThread SubMac](https://github.com/openthread/openthread/blob/main/src/core/mac/sub_mac.cpp).
- Nordic's BSD-3-Clause `nrf_802154` reference supplies RX END latency, RSSI/CCA/ED temperature
  corrections, ADDRESS as TX-start capture, and clearing DISABLED before a new DISABLE task.
  nRF MicroZig uses a dedicated TIMER3/PPI schedule and caller-owned FIFO with legacy ACK only.
  Nordic has a larger transceiver state machine and scheduling/coexistence machinery outside
  this interface. See the [port README](../../port/nordic/nrf5x/README.md) reference list and
  [duration header](https://github.com/zephyrproject-rtos/hal_nordic/blob/master/drivers/nrf_802154/driver/src/nrf_802154_procedures_duration.h),
  [RSSI conversion](https://github.com/zephyrproject-rtos/hal_nordic/blob/master/drivers/nrf_802154/driver/src/nrf_802154_rssi.c)
  and [transceiver](https://github.com/zephyrproject-rtos/hal_nordic/blob/master/drivers/nrf_802154/driver/src/nrf_802154_trx.c).

## Shared patterns

- Reuse synchronized singleton ownership, compile-time vectors and fixed-queue
  handoff. Use Deinit guard to drain unread results before releasing
  routing. A quarantined owner keeps its routing and storage until chip reset. See [Interrupt handling and ISR routing](interrupts.md).

### Driver and evidence

- Capture validity across an emergency RADIO POWER reset during teardown is not specified.
- What is the worst-case time from a CPU-visible RADIO event latch to CAPTURE updating a CPU-readable TIMER3 CC at prescaler 4 (PS v1.11 §§6.16, 6.30.1, 6.30.3)? `R:capture_checks` is not derived from such a bound.
- If ADDRESS→RSSISTART overlaps a software RSSISTART on the same RX arm, does hardware keep an in-packet RSSISAMPLE through END? PS v1.11 §6.20 lists a typical period and does not specify overlapping task arbitration.
- Immediate ACK launch has no measured or derived worst-case END service, including capture validation, settings copy and compare/PPI arm margin for the four-tick cutoff (`R:Radio.arm_auto_ack`).
- RX readiness for the peer's ACK has no worst-case PHYEND→DISABLED→ISR→RX readiness budget (`R:Radio.handle_tx`).
- The shared RADIO wait check is bounded by CPU iterations (`R:transition_checks`), not by a budget derived from maximum RADIO transition latency and the supported CPU clock.
- The cached public clock before its first valid sample, and fault/terminal ordering for a teardown during a blocking call (including a fault discovered by now_us), are not pinned down.
- The 20 ms HF crystal startup cap in `R:Radio.init` has no documented worst case for the selected crystal and board.
- TEMP and RNG STOP completion bounds, TEMP cadence and RNG startup/byte bounds are software policy, not established bounds (`R:csma_seed`, `R:Radio.init`).
- Does PS v1.11 §6.20 permit an IEEE 802.15.4 ADDRESS or FRAMESTART indication in RXIDLE without START, or with START but RX EasyDMA suppressed, without writing a frame to RAM? Buffer-missing RX has no way to report an individual drop.

### OpenThread platform (#50)

- Propagate a refused EnergyScan or wrap the scan entry so `SubMac::EnergyScan` does not enter its scan state on refusal. OpenThread's capability branch ignores the Platform return.
- Zero reused RX/TX timestamp fields before fault callbacks and keep proven TxStarted. RX abort is ReceiveDone(null frame, OT_ERROR_ABORT). TX abort is TxDone(original TX frame, no ACK, OT_ERROR_ABORT). Apply these arguments to diagnostics and test reuse after a timed event through OpenThread and Spinel.
- Commit Platform state and retire TX/scan tokens before completion or fault callbacks, including staging expiry. Callbacks drained after Disable observe Platform Disabled, including re-entrant Receive and scan calls.
- GetRssi returns OT_RADIO_RSSI_INVALID unless Platform state is Receive, including during listening backoff where the HAL may have a sample.
- EnergyScan widens aScanDuration from u16 ms to u32 and multiplies by 1000 for the HAL duration in µs.
- Handle the zero-duration `Mac::PerformEnergyScan` Receive→GetRssi channel-hop path even with energy_scan advertised. Require settled RX before sampling, or restrict this scan profile. Test consecutive channel hops.
- Reconcile live HAL Disabled before state-dependent Platform queries and guards and after synchronous HAL faults. Map Aborted Sleep/Receive to OT_ERROR_FAILED and RSSI to the invalid sentinel. Enable/Disable HardwareFault uses the fatal error path.
- Settings across a HAL fault: the adapter must reconcile requested vs committed settings (including SourceMatchController pending flags and enable state) before re-enable, with RX closed until replay completes; typed rejections (invalid power or threshold, NoSpace, NotFound) must not be retained for replay.
- A HAL setter whose prologue faults applies nothing. Typed setters surface the fault distinctly from NoSpace/NotFound.
- A synchronously refused Platform TX or scan owes no callback. Every accepted request owes one terminal callback, including OT_ERROR_ABORT for TX or OT_RADIO_RSSI_INVALID for a scan if HAL admission fails or expires.
- A HAL-admitted scan ending in energy_scan_failed(.aborted) maps to one EnergyScanDone(OT_RADIO_RSSI_INVALID) callback.
- EnergyScan refusals while Disabled, active or staged, or unsupported return OT_ERROR_INVALID_STATE, OT_ERROR_BUSY or OT_ERROR_NOT_IMPLEMENTED respectively and owe no callback.
- Own stable TX frame and PSDU storage through TxStarted and TxDone, and respect the borrowed HAL RX/ACK lifetime across callbacks.
- Derive the supported hardware mask (0x07fff800) from valid channels and apply board or regulatory restrictions and preferred-channel configuration.
- SubMac finishes TX before requesting Receive. Platform Receive in Transmit or Disabled returns OT_ERROR_INVALID_STATE. Sleep is allowed from Receive, returns Busy during Transmit and InvalidState while Disabled. Disable requires Sleep per radio.h.
- Per radio.h, Platform Transmit starts from Receive when idle RX is on or sleep-to-TX is unsupported, and from Sleep otherwise. Apply the accepted/refused callback rule above.
- TxStarted takes the instance and original frame without a timestamp argument. Map TxDone sent/acked to success, no_ack to OT_ERROR_NO_ACK, channel_access_failure to OT_ERROR_CHANNEL_ACCESS_FAILURE and aborted/failed to OT_ERROR_ABORT. Apply the diagnostic and fault arguments above.
- ReceiveDone supplies the OT PSDU with FCS and HAL metadata, with enhanced ACK fields clear. Map overrun, per Overrun report, to OT_ERROR_NO_BUFS, aborted to OT_ERROR_ABORT and optional FCS error to OT_ERROR_FCS, all with null frame. Use the same mappings for diagnostics.
- Use the optional default version string, board factory EUI-64 and the same reported capability mask on-chip and on RCP. Keep bad-FCS delivery off for the Thread MAC. OpenThread owns MAC security keys/counters and supplies secured bytes.
- Map absent ReceiveAt and FEM to OT_ERROR_NOT_IMPLEMENTED with no window-ended callback. Coexistence uses the API's unsupported or false result. Keep CSL scheduling disabled and report enable/reset unimplemented. Channel-power and region controls need board policy or an unimplemented result.
- Report 0/0 bus speed and latency on-chip with no change callback, and use Spinel transport timing and change notification on RCP.
